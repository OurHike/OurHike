# v1.3.4 — Kuwohi

_1 change since v1.3.3._

**A second hotfix, cut from v1.3.3 rather than from `main`** (RELEASING.md §11a).
Like v1.3.3, it changes ourhike.org's homepage and not the app.

v1.3.3 put impact.com's verification on the homepage in two forms: a
"text content" line inside a hidden paragraph, and a meta tag written with
double quotes. Impact did not verify the site against that page. The maintainer
confirmed Impact holds `https://ourhike.org`, so the address was not the
problem, and asked for the meta tag alone, written exactly as they supplied it.

## What changed for a hiker

Nothing in the app. It is v1.3.2's app, rebuilt: the version under **About this
build** in Settings now reads 1.3.4.

On ourhike.org, the homepage's `<head>` now carries Impact's meta tag byte for
byte as the maintainer supplied it, single quotes included:

```html
<meta name='impact-site-verification' value='ef20c667-05ef-4435-af33-c57e73b5f39c'>
```

The hidden "Impact-Site-Verification" text line is gone. The page looks the same
to a visitor.

## What is not validated

<!-- RELEASING.md §8d: this section is never empty, and a release whose author believes

- **Why v1.3.3 did not verify.** Nobody saw Impact's reason. The hidden text,
  the meta tag's quote style, a stale check on Impact's side and a code that
  changed are all possible. This release acts on one of those.
- **Whether the quote style matters to Impact's checker.** To any HTML parser,
  single and double quotes make the same element. Only a checker that
  string-matches the snippet would tell them apart. The tag is written exactly
  so that question doesn't have to be answered.
- **Whether the value is right for the meta method.** It is the id Impact
  showed the maintainer for the text line, and the maintainer supplied this tag,
  with that value, on 2026-09-29.

Everything [v1.3.2's notes](https://github.com/OurHike/OurHike/releases/tag/v1.3.2)
list under this heading is still true. This release changes none of the app code
it describes.
