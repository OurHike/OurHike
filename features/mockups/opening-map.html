Every Trail We Have Mapped

The maintainer's ask, 27 August: the opening map is the trails — all of them — and not the waypoints; keep the whole-country camera cheap, without taking away the view of an entire trail. Three options for the display half, one measured artifact for the data half, and the finding that makes the tension dissolve: every whole-trail camera this build can offer already sits below the seam.

Shouldn't all the trails be displayed by default?" — which takes Option A and the artifact together. What shipped: export_nearby_trails.py writes network_overview.geojson (source × blaze × status, published under the same licence gate as its parent), the client draws it below the seam through the shared expressions with the stewards' credit following it, POI_DOT_MIN_ZOOM moved to the seam, and the legend's sentence flipped with the layer — the plain form ("Waypoints appear from a closer zoom"); the coverage-mileage sentence waits for a figure that cannot outrun the map.

Still open, deliberately: the three route labels (decision 3 — no trail-name layer exists below the seam yet), and the 7.3 MB fetch deferral (decision 4 — handed to #552 with the measured numbers). The frames and options below are kept as drawn, as the record of what was weighed.

What the opening camera draws today — and what it is about to

The app opens on CORRIDOR_BOUNDS, which lands at z4.87 on a phone (#598's measurement; the frames on this page reproject the published geometry and land on the same number). The stipple was the right answer to an empty screen, and its own docstring already carries the caveat that matters here: "dots are texture, not a subject."

The texture is about to stop being honest. #1097 — Ship DEC's and OPRHP's waypoints merged this morning: 8,480 network waypoints join the same map source the dot rank draws. But the trails those waypoints sit on draw only at z≥9 — #950's deliberate floor, so 21,805 lines cannot smear across the corridor view. The two decisions were each right alone. Together they put 8,480 places on the opening map with no trails under them.

the askinverted

The ask is today's split, inverted — and every piece already exists

Today the view below the seam shows places without their trails. The ask is trails without their places. That is not a new design so much as the existing one finishing its own thought: the seam is measured and shipped (POI_PIN_MIN_ZOOM = 9), the corridor view has real subjects now — thirty club sections (#594), the named highlights (#595) — and #869 — Publish a corridor-view centerline so first run has a trail line in about a second already established the artifact shape this needs: the same geometry, simplified to 100 m, drawn below the seam only, 81× smaller.

What is missing is one artifact and one constant: the network's own overview, and a floor for the dot rank. The three ways to set that floor:

The artifact, measured

measured 255,263 gzipped bytes for the whole network's opening-view lines. The live nearby_trails.geojson (7.3 MB gzipped, 21,805 features), run through write_overview's own method — EPSG:5070, 100 m Douglas-Peucker, 4-decimal coordinates, merged per (source, blaze, status): 31 features, 480,115 → 57,226 coordinates. pipeline/spike_network_overview.py reproduces it.

measured Closures ride along for 328 bytes. Keeping trail_status in the merge key costs 25 → 31 features and keeps the 224 closed features (48.4 line-miles) distinct, so the barrier tape can draw below the seam too — an overview that painted closed ground open-looking would be the display outrunning its source.

measured The opening camera already frames all of it. The network's bounds — W −79.59 S 40.50 E −71.86 N 45.01 — sit inside CORRIDOR_BOUNDS. No camera change.

reasoned ≈306 KB for every line on this screen (51,068 B published A.T. overview + 255,263 B network) — about 0.2 s at the 12 Mbps #869 measured transfer at, against 2.8 s for trails.geojson alone.

What it takes. Pipeline: export_nearby_trails.py writes network_overview.geojson the way export_trails.py's write_overview already writes the A.T.'s. Client: one config key, a fetch-and-verify like lib/nearbyTrailData.ts's (cached — this layer is standing, not a sketch), drawn through the same blaze/width/ghost expressions with maxzoom 9 where the real network's layers carry minzoom 9. The two properties the paint reads — source, blaze_color — are on every overview feature already.

This half-reverses #603, twelve days later — say so plainly

reasoned Two things changed since #603 put dots on the corridor view. The subject it was compensating for now exists — clubs (#594) and highlights (#595) both draw below the seam — and #1097 changed what the stipple is: from "every waypoint on the trail you see" to "every waypoint, mostly on trails this view refuses to draw." #603's own docstring called the dots texture rather than a subject and took the trade because the alternative was an empty screen. The alternative is no longer an empty screen.

The dot rank itself is untouched above z9 — "a pin or a dot and never as neither" is not reopened, and the 1.2 px corridor stipple this removes is itself tagged @unvalidated in poiLayers.ts: nobody has looked at it on a phone in sunlight.

Weighing the band

What B buys is one honest thing: at state scale, density is real information — the Catskills read busier than the Alleghenies because they are. What it costs is that the legend can no longer say one true sentence about the band, and that the thresholds join the pile #105's outdoor pass already owes answers to.

A answers the same question with the highlights — a curated "worth going here" beats an inferred "many dots here", which is CORRIDOR_VIEW.md's whole argument against density displays. Recommendation: A, with B kept in the drawer for the day the highlight list feels too thin at state scale.

Option C, in one paragraph. Keep #603's stipple for the chosen system only. It is the most defensible form of the dots — but no POI feature carries a system attribute today, so it needs a new property plus a second filter clause, and it re-softens "a complete map of something else." It becomes interesting again when #558 — Let a hiker take the stretch they are walking makes "chosen" a real variable. Not now.

Where the whole-trail waypoint question lives instead

"Show me every shelter on the A.T." is a real question — and a 2,197-mile map was never its answer. The app already has three better homes for it, each one decided in its own document:

  • The Plan tab's whole-trail ribbon (#790) — the linear view, where 2,197 miles lay out as a scroll rather than a squint.
  • Search — for the hiker who wants one place, not a texture.
  • The highlights on this very view — the curated "worth going here", with a mile range and a Naismith time derived on the phone.

#532 already refused the two texture answers — cluster bubbles and viewport-driven lanes — for this exact camera, and CORRIDOR_VIEW.md's refusal reads on the dots too: "a hiker at a kitchen table looking at fourteen states is not asking how many privies are in Virginia."

A phone that never looks at New York above z9 pays 7.3 MB of wire per publish and a 23.5 MB parse per map build for lines it never draws — with the overview standing in below the seam, that fetch could wait for the first camera that can actually draw the real thing. What keeps this from being a one-line change is offline: a hiker who downloads a sheet at home must still get the network eagerly with it, and what a named download contains is exactly #552 — Decide the unit of offline coverage, and write it down. Decide it there, not here.

5decisions

The decisions, separated

1 · Where does the dot rank stop?

A (the seam, z9), B (a fade across z5.5–9), or C (chosen system only). All three end the whole-country stipple; they differ only in the z6–9 band.

recommendation A. One seam, one legend sentence, and the collision #1097 loaded — 8,480 dots over undrawn trails — never ships. B stays in the drawer; C waits for #558 to make "chosen" a variable.

2 · Publish network_overview.geojson?

255,263 gzipped bytes, measured, by the exporter pattern #869 already established — with trail_status in the merge key so the 224 closed features stay tape-able below the seam. Without it, "all the trails we have mapped" is only the A.T. at the opening camera, and the network stays invisible below z9 exactly where a new user forms their first idea of coverage.

recommendation Yes — it is the data half of the ask, and the whole artifact costs less than a twentieth of the file it stands in for.

3 · Names on the opening map?

The frames above label the A.T. and point one label at the network mass; the z7 frame names the two marquee routes. Today no trail-name layer exists at any zoom (recorded in map/nearbyTrails.ts), so this is new ink, and it is the one piece of this page with a real offline caveat: labels need glyphs, which the live background supplies and the offline sheet does not. @unvalidated nobody has drawn text at z4.87 on a phone; legibility over the ghosted mass is a guess until a frame is rendered.

recommendation v1: label the three named routes only (A.T., Long Path, Highlands), below the seam only. Region and park names are #557 — Draw the map from several coverage units's subject, not this change's.

4 · Defer the 7.3 MB network fetch?

With the overview standing in below z9, nearby_trails.geojson is only needed at cameras that can draw it. Fetch-on-first-need would take the cold run from 14.7 MB to ~7.2 MB for every phone that stays on A.T. ground — but it intersects offline coverage, which is #552's decision.

recommendation Not in this change. Hand #552 the measured numbers and let the offline unit decide what a download must contain eagerly.

5 · What does the legend say below the seam?

Today: "Waypoints show as dots at this zoom. Zoom in to see what each one is." — true since #603, false again the moment the dots go. The sentence has flipped twice already (#528, #603), so it should flip with the layer, in the same commit, with the coverage line the view finally has the data to say.

recommendation "Trails from five organizations — the A.T. end to end, and 7,670 miles around it. Waypoints appear from a closer zoom." The mile figure comes off the same artifact the lines do, so the sentence can never outrun the map.
